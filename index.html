使用与检查

应该选哪种文件？

硬件配置：优先选择你主动导出的 sysdiagnose 诊断包。也可在本机解压，选择 ioreg 中的 IODeviceTree.txt、IOService.txt，以及电池相关文本。

电池记录：在「设置 → 隐私与安全性 → 分析与改进 → 分析数据」中，寻找 Analytics 开头的文件，分享并保存到「文件」。

JetsamEvent 是内存终止报告，App 名称开头的文件通常是应用诊断；不应把它们当作完整硬件配置。网页无法自动扫描系统的分析数据目录，只读取你选中的文件。

一次最多 20 个文件。每个文件分别出报告，不自动混合不同设备或日期。单文件与展开扫描预算为 2 GiB；ZIP64、加密包、二进制 plist 暂不支持。几百 MB 的包可尝试分块读取，但实际可用性仍取决于设备内存和浏览器。

如何导出 sysdiagnose？

参考 Apple 官方的「Sysdiagnose for iOS/iPadOS」说明，按你的机型生成诊断记录，再从分析数据分享并保存到本机「文件」。生成方式与等待时间依机型和系统不同。

供应商识别依据

「日志直接记录」表示文件中写出了厂商或型号文本，不是本工具独立检测。「社区映射」表示按部件代码推断的候选，规则可能不适用于新机型；可以关闭。

当前屏幕规则包含 G9N / G9P / G9Q → 三星候选，GVC / GH3 → LG 候选。电池、内存、存储与摄像头优先提取明确的厂商、型号字段；不对未知序列号前缀猜测厂商。传感器供应商、模组厂与电芯厂应依字段分别理解。

离线使用与隐私

在 Safari 分享菜单中「添加到主屏幕」。首次联网看到“离线资源已就绪”后，可尝试断网打开。系统可能清除网站缓存。

原始文件只在本地工作线程中读取，不发送、不持久化，也不会进入离线缓存。序列号默认遮盖。只有点击「保存到此设备」才在浏览器数据库保存脱敏结果，可以逐项删除；清除本次记录仅清空内存。

导出不包含完整日志、原始设备标识或完整部件序列号。文件中的时间、地区和容量等字段仍可能透露设备信息，分享前请检查。初次加载和更新会请求 GitHub Pages 的应用资源，托管方可能记录 IP 等访问元数据。
